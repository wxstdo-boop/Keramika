# Участие в проекте

Спасибо, что хочешь помочь. Правил немного, но они важны — из-за них
приложение одинаково выглядит на всех устройствах.

## С чего начать

1. Открой [Issues](https://github.com/wxstdo-boop/Keramika/issues) — возможно,
   баг уже описан или обсуждается.
2. Посмотри [доки по архитектуре](docs/ARCHITECTURE.md), чтобы понять, где
   что лежит.
3. Сделай форк, ветку от `main`, и пришли PR.

## Окружение

```bash
flutter pub get
flutter analyze     # должен быть чист
flutter test
flutter run
```

Подробности — в [docs/BUILD.md](docs/BUILD.md).

## Стиль кода

- `flutter_lints 6.0.0` включён. `flutter analyze` не должен ругаться ни на
  одну строку.
- Комментарии, doc-комментарии и тексты в UI — **по-русски**. В коде уже так,
  не выбивайся.
- Имена переменных, классов и файлов — по-английски.
- Файл не должен раздуваться. Если экран перевалил за ~800 строк, это сигнал
  вынести виджеты в `lib/widgets/`.
- Логику не прячь в `build()` — держи в отдельных методах и `_State`-полях.

## Коммиты

Сообщения по-русски, в прошедшем времени, с большой буквы. Примеры из
истории этого проекта:

```
Плавное время будильника, отдача шапки, переработан значок автоэкспорта
Убрать белые полосы под таблеткой, стрелка у тултипов, плавный пин привычек
Автообновление через GitHub Releases + починка сборки разделов
```

## Локализация

Любой новый текст в интерфейсе обязан появиться сразу во всех трёх словарях
`lib/l10n/translations.dart`: `en`, `ru`, `fr`. Забытый перевод — самый
частый баг в PR.

## Ассеты

- Иконки и звуки — только в `assets/`, с добавлением в `pubspec.yaml`.
- Растровые файлы сжимай: телефон грузит их с flash-памяти.
- Скриншоты для README — в `docs/screenshots/`, инструкция там же.

## Чего не делать

- **Не коммитить** собранные APK, логи, ключи и `keystore.jks`. Всё это уже в
  `.gitignore` — не обходи его.
- **Не менять `third_party/`** без необходимости. Там форки с важными
  правками; подробности в [docs/BUILD.md](docs/BUILD.md).
- **Не поднимать `versionCode` в случайном PR.** Это делается только при
  релизе, см. [docs/RELEASE.md](docs/RELEASE.md).
- **Не приносить свои ключи ИИ.** Провайдер выбирается пользователем в
  настройках, ключи хранятся только на устройстве.

## Проверка перед PR

- [ ] `flutter analyze` — `No issues found!`
- [ ] `flutter test` — всё зелёное
- [ ] Новые строки переведены на `en` / `ru` / `fr`
- [ ] В `git status` нет мусора
- [ ] Изменения, которые видно глазом, проверены на устройстве

## Код поведения

Мы не собираем данные пользователей. Приложение не требует аккаунта и не
отправляет ничего на свои серверы. Единственные сетевые запросы — к ИИ-провайдеру,
которого выбрал сам пользователь, и к GitHub за обновлениями. Всё новое,
что ходит в сеть, должно быть явно описано в интерфейсе и отключаемо.
